# Test suite

The repository currently has one test module, `test_share_dir_nfsfacl.py`, with
26 tests for `share-dir-nfsfacl.py`. The suite uses Python's standard-library
`unittest` framework and does not require a live NFS server.

## Running the tests

From the repository root:

```bash
python3 -m unittest -v tests/test_share_dir_nfsfacl.py
```

Filesystem fixtures are created below
`~/nfsacl-test/share-dir-nfsfacl-tests` by default. Set
`SHARE_DIR_TEST_BASE` to use a different location:

```bash
SHARE_DIR_TEST_BASE=/tmp/share-dir-nfsfacl-tests \
    python3 -m unittest -v tests/test_share_dir_nfsfacl.py
```

Each test case gets its own temporary directory, which is removed after the
test. Commands that could contact an NFS server, query account databases, or
modify ACLs are mocked. The CLI help test is the only test that starts the tool
in a separate process, and it only runs `--help`.

## Test infrastructure

`load_tool` loads `share-dir-nfsfacl.py` through `importlib`, because the
hyphens in the filename prevent a normal Python import.

`HomeDirectoryTestCase` creates a private temporary filesystem tree for every
test. It resolves the fixture root to its canonical path so the expectations
also work on systems where home directories are exposed through an NFS or
autofs alias.

## PathMappingTests

- `test_longest_nfs_mount_wins` verifies that mount detection selects the most
  specific matching NFS mountpoint when mounts are nested.
- `test_local_path_is_mapped_below_export` verifies translation from a local
  path below a mountpoint to the corresponding server-side export path.
- `test_allowed_root_rejects_root_itself_and_sibling_prefix` verifies that a
  mutating operation cannot target the allowed root itself, accepts a child of
  that root, and does not mistake a similarly named sibling for a child.
- `test_deepest_allowed_root_is_selected` verifies that nested allowed roots
  are resolved to the deepest matching root. This root is later used as the
  boundary for parent ACL changes.

## SubjectResolutionTests

- `test_explicit_group_only_queries_group_database` verifies that an `@group`
  subject is looked up only as a group.
- `test_bare_name_prefers_user_over_group` verifies that an unprefixed subject
  is first looked up as a user and that a successful user lookup stops further
  group lookup.
- `test_missing_subject_exits_with_clear_message` verifies that a subject which
  is neither a local user nor a local group causes a clear `SystemExit` error.

The account-database calls are mocked; these tests do not invoke the system's
real `getent` command.

## TargetCollectionTests

- `test_non_recursive_collection_stops_after_immediate_children` verifies that
  non-recursive target collection includes the selected directory and its
  immediate children, but not deeper descendants.
- `test_recursive_collection_includes_entire_tree` verifies that recursive
  collection includes deeply nested directories and files.
- `test_file_has_no_default_acl_target` verifies that a file is an access-ACL
  target but is not included in the directory list used for default ACLs.

These tests create ordinary temporary files and directories but do not apply
ACLs to them.

## CommandConstructionTests

- `test_readwrite_builds_access_and_default_commands` verifies the exact
  recursive `setfacl` access and default ACL commands for a read-write grant,
  including the default owner entry.
- `test_owner_is_not_duplicated_in_default_acl` verifies that sharing with the
  owner does not add a duplicate default ACL entry for that owner.
- `test_undo_builds_access_and_default_removals` verifies the exact access and
  default ACL removal commands generated by `undo`.
- `test_chunking_keeps_every_item_once` verifies that command-line length
  chunking retains every path exactly once.

These tests compare generated command strings and never execute `setfacl`.

## ParentAclTests

- `test_traverse_acl_stays_inside_allowed_remote_root` verifies that the
  minimal `--x` traversal ACL is applied only from the configured remote
  allowed-root boundary downwards, never to a broader parent.
- `test_unrelated_boundary_does_not_run_ssh` verifies that no SSH command is
  attempted when the supplied boundary is not an ancestor of the remote
  target.

SSH execution is mocked in both tests.

## ShowFormattingTests

- `test_human_output_normalizes_and_sorts_principals` verifies conversion of
  sample `getfacl` output to the human-readable read/write/execute view. It
  covers owner and owning-group normalization, named entries, omission of
  default entries, and deterministic user-before-group ordering.
- `test_show_raw_passes_remote_output_through` verifies that `show --raw`
  writes the original `getfacl` output unchanged and returns its status.

## CliTests

- `test_help_runs_as_a_real_subprocess` executes `share-dir-nfsfacl.py --help`
  in a separate Python process and verifies a successful exit and the presence
  of key actions in the help text.
- `test_flags_work_before_and_after_action` verifies that common options such
  as `-r` are accepted both before and after the action name.
- `test_dry_run_readwrite_writes_audit_but_never_calls_ssh` exercises the
  high-level recursive read-write dry-run flow. It verifies that SSH is not
  called and that the JSON audit record contains the action, translated remote
  path, recursion flag, and dry-run flag.
- `test_path_outside_allowed_root_stops_before_mount_detection` verifies that a
  path outside the configured roots exits with status 3 before NFS mount
  detection.
- `test_missing_path_stops_before_any_remote_processing` verifies that a
  nonexistent path exits with status 2 before mount detection, subject
  resolution, or SSH processing.
- `test_symlink_uses_canonical_target_path` verifies that a valid symlink is
  accepted and that the remote `getfacl` command uses the canonical target
  path rather than the symlink name.
- `test_dangling_symlink_is_rejected_as_missing` verifies that a dangling
  symlink exits with status 2 before mount detection or SSH processing.
- `test_symlink_cannot_escape_allowed_root` verifies that a symlink located
  below an allowed root cannot be used to target an existing path outside that
  root. The command exits with status 3 before mount detection or SSH.

## Scope

The suite covers `share-dir-nfsfacl.py`. It does not currently test
`share-dir.py` or `share-dir-remote.py`, and it deliberately does not perform
live NFS, SSH, `getfacl`, or `setfacl` integration tests.
